# ShikshaSetu — Full Stack AI Mentor Workspace

## Start here
- `index.html`: login / account setup development preview.
- `dashboard.html`: full student-success workspace.
- `backend/`: Java 21 + Spring Boot 3.5.6 + Spring Data JPA + H2 + Weka.
- `assets/nature-gallery/`: all 24 local nature scenes.
- `nature-gallery.js`: shared image rotation, scene controls and saved preferences.
- `AI-MODEL-RESEARCH.md`: research rationale, validation and governance plan.

## Run in VS Code (Windows PowerShell)

1. Extract the entire ZIP. Keep `assets/`, `backend/`, `nature-gallery.js`, `styles.css`, `login.css` and both HTML files together.
2. Open the extracted `ShikshaSetu` folder in VS Code.
3. Start the backend in Terminal 1:

```powershell
cd backend
mvn clean package
mvn spring-boot:run "-Dspring-boot.run.profiles=dev"
```

4. Start the frontend in Terminal 2 using VS Code Live Server on `http://127.0.0.1:5500` (or run `python -m http.server 5500` from this root and open `http://localhost:5500`).
5. Open `index.html`, sign in/create a preview account, then enter the existing workspace.

The dev H2 database persists under `backend/data/`. H2 console: `http://localhost:8080/h2-console`.

## AI model
The backend contains a trainable Weka Random Forest for one explicitly defined target: a drop of at least 10 percentage points in next-period subject-average marks compared with the current reporting period. It uses eight academic/engagement features and keeps all snapshots from one pseudonymous student together in a grouped train/test holdout. The original rule-based score remains intact as a baseline and is used while no ML model is trained.

In **AI Admin Console**, upload an approved anonymised labelled CSV using the supplied template to train/replace the model. The template is `backend/ai-training/training-template.csv`. The console displays training status and holdout metrics. When a model is loaded, the Mentor Support Loop uses its dedicated ML assessment endpoint and persists assessment history. The UI distinguishes observed feature values from model feature importance; it does not falsely present inputs as SHAP contributions.

The package does **not** contain a pre-trained institutional model. Training requires real, approved longitudinal labels. The 100-row / 30-student checks are prototype validation guards, not evidence that the data is statistically sufficient. The probability is not calibrated. No accuracy claim is made before training and validation.

## Important development / production boundary
Login authentication is still a browser-only preview. The chat assistant is not a connected LLM. Rule-based support templates are not generated by the Random Forest. Mood check-ins are separate and are not model inputs. A live urgent-safety escalation is not connected to a staffed human responder. Do not use real identifiable student data or expose the training endpoint publicly until authentication, authorisation, encryption, auditing, privacy/legal review, retention and deletion controls, temporal/external validation, calibration, fairness review and human-governed intervention policies are implemented.

See `AI-MODEL-RESEARCH.md` and `backend/ai-training/README.md` before training.

## Light and dark mode

ShikshaSetu uses a shared `theme-controller.js` on both the login and workspace pages. The current selection is saved under `shikshasetu-theme`, applies before the page is painted, and synchronizes between open tabs. The header theme button and Appearance dialog control the same preference. Light mode uses the original luminous botanical glass surfaces; dark mode uses deep emerald glass, brighter moss rims, pale typography, dark inputs, and a dark table treatment. The 24-scene nature gallery retains its current scene and uses a theme-specific contrast veil.
